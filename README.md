# 一起出发 · GoTogether

部门活动的去程登记网站。活动页采用 2.5D 出发广场：点击汽车查看司机、出发点、时间和乘客，选择地铁或人物模型登记其他交通方式。汽车使用本地透明图片，地铁和人物由 CSS 绘制，页面运行不依赖外部图片、字体或 CDN。

## Windows 上使用

需要 Python 3.11 或更新版本，以及首次安装依赖时可用的网络连接。

1. 双击 `setup.cmd`。脚本创建项目虚拟环境，安装依赖，并提示设置共享管理员账号和密码。密码输入时不显示字符。已有配置会保留。
2. 双击 `start.cmd`。首次启动自动创建空数据库，不写入演示活动。
3. 本机打开 `http://127.0.0.1:8080`。同事访问 `http://这台电脑的内网IPv4地址:8080`。可以在 Windows 的网络属性中找到 IPv4 地址。
4. 填写姓名、创建活动，把活动页中的“分享活动”链接发给同事。

承载网站的电脑需保持开机、联网并运行启动窗口。按 Ctrl+C 或关闭窗口停止网站。`0.0.0.0` 是监听地址，不能作为浏览器访问地址。

如同事无法访问，检查双方是否在可互通的内网，以及 Windows 防火墙是否允许该 Python 程序的域网络/专用网络入站连接。脚本不会修改防火墙。手机需要连接可访问该电脑的公司 Wi-Fi。

配置保存在 `instance/config.json`。修改端口后重启；默认端口为 8080。可通过 `GOTOGETHER_INSTANCE` 环境变量指定另一个本地数据目录。请使用本地磁盘保存 SQLite 数据，不把运行中的数据库放在共享网络盘。

HTTP 内网地址下的剪贴板自动复制可能不可用，分享按钮会显示可手动复制的完整链接。

## 身份与权限

- 普通成员输入姓名使用，不设置个人密码。姓名首尾空白会去除，按 Unicode NFC 规范化，其余字符精确匹配。同名视为同一个人；真正同名的同事可填写“张伟（研发）”等区分名称。
- 打开网站首页会进入姓名入口。当前浏览器会话内保留身份，右上角可切换姓名；换设备输入同一姓名可管理原记录。会话最长有效 12 小时。部分浏览器的“恢复上次会话”可能保留会话 Cookie。
- 活动创建者按姓名识别，可以修改活动信息和开关登记。司机可以将等车区的成员直接接到自己的车上，也可以将本车乘客单独移回等车区；其他人员调整由管理员操作。
- 管理员在 `/admin` 登录，管理全部活动、车辆、人员和待确认提醒。后台关闭后仍可修改人员安排。
- 管理员登录后，活动列表中的“可视化调度”直接进入出发广场，无需再填写普通成员姓名。广场会显示“管理员调度模式”，可以管理所有车辆和人员；退出管理员登录后恢复普通权限。
- 管理员可把等车人员、已有乘客、公共交通或其他方式的人员拖到任意有空位的车辆，也可在详情中选择目标车辆。乘客可单独移回等车区，车辆和司机可进入编辑或取消页面；所有人员都可调整方式或撤销登记。表单保存后返回广场，登记关闭后也可操作，座位容量和一人一份登记的限制仍然适用。
- 普通用户的姓名是部门内部约定的身份标志；管理员权限另外通过密码验证，输入管理员账号作为普通姓名不会取得后台权限。

管理员密码用 Werkzeug 哈希保存。修改密码：

```powershell
.\.venv\Scripts\python.exe manage.py reset-admin
```

重启网站后新密码生效，原管理员会话失效。普通用户姓名会话不因此改变。

## 出行规则

- 只统计去程；一场活动、一个姓名只有一份有效登记。
- 出行方式为自己开车、拼车、等车、公共交通、其他自行前往；还可请求管理员协助。
- 车辆必填可搭载人数（不含司机，允许 0），出发点、出发时间、车牌和备注选填。车牌最多 20 个字符，显示在车辆模型、车辆详情和后台车辆列表中。
- 创建或编辑车辆时，可以选择劳斯莱斯幻影、农用三蹦子、小米 SU7、尊界 V800、卡丁车、雅迪电动车、宝马马车、五菱宏光、大运卡车、理想 MEGA、凯迪拉克 CT5、比亚迪汉、马自达 929、三体水滴十四种外观，选项带图片预览。CT5 和马自达 929 使用默认黑色，马自达素材为 HC 代四门轿车。新车默认使用小米 SU7，已有车辆保留选定的外观；司机和管理员均可更换，停车场会同步外观变化。外观不改变实际可搭载人数，卡丁车、电动车和马车同样按填写的容量安排乘客。
- 理想 MEGA 在停车区跨两个车位，车身居中压线展示。大屏每排三个车位，其余屏幕每排两个；当前排差一个位置时，末尾普通车辆顺延到下一排，为 MEGA 留出两格。多辆 MEGA、实时同步和窗口宽度变化均按同一规则重新排布，实际车辆编号、容量和乘客安排不变。
- 有空位即可加入，无需司机确认。司机不能再加入自己的车辆。
- 每次进入车辆编辑页面，首次选中尊界 V800 时弹出“车辆选择确认”声明；编辑已有 V800 时也会提示。同一页面内同意后，反复切换车型和保存不再弹出；离开后重新进入（包括浏览器返回）需重新确认。取消会恢复之前的车型，其他车型正常选择；普通成员和管理员遵循同一规则。
- 小米 SU7 可选卡布里蓝（默认）、霞光紫、雅灰、珍珠白和曜石黑。配色透明图参照新一代 SU7 官方展示制作，选择颜色时即时预览，保存后同步到活动页。已有 SU7 升级后使用卡布里蓝，换色保留车辆编号和乘客安排。
- 雅迪电动车可选原版（默认）和“美团外卖 · 黄色外卖箱”皮肤。外卖版保留原车配色，增加带袋鼠图案与“美团外卖”标识的亮黄色后置外卖箱；选择时即时预览，保存后同步到停车区和车辆详情，司机与管理员均可调整。
- 比亚迪汉可选红色原版（默认）和滴滴出行涂装。滴滴版采用白色车身、橙色标记与深灰色“滴滴出行”门贴，选择时即时预览，保存后同步到停车区和车辆详情，司机与管理员均可调整。
- 乘客主动加入比亚迪汉的滴滴版时，会弹出专车欢迎窗口，输入任意四位数字后确认上车，`0000` 也可使用。数字仅用于本次趣味确认，不保存；取消弹窗保留原安排。点击、拖动和出行表单均遵循此规则，已在同一辆车上的乘客修改信息无需重复输入；司机接人和管理员调度沿用原流程。
- 换车或修改方式会更新原登记；新车满员或已被取消时，事务回滚，原安排保留。
- 等车区公开显示姓名、上车地点、可选时间和备注，地点和时间均选填。可选时间为活动当天的时间，只填一项表示一个时间点，两项都填表示时间段，两项留空表示时间灵活。
- 司机点击小人后可“接到我的车上”，桌面浏览器也可拖动小人到自己的车辆。接人不需要乘客确认，成功后立即占用座位。接人时检查活动状态、车辆归属、座位和乘客登记版本；已被接走或修改需求的记录需刷新后再操作。
- 登记开放时，等车者可把自己的小人拖到任意有空位的车辆上，也可点击自己的小人，在详情中选车并点击“上这辆车”。普通等车成员只能移动自己；满员车辆不接收拖动。上车后保留地点、时间和备注，司机可在车辆详情中查看。
- 乘客可在已加入的车辆详情中点击“退出车辆”，立即释放自己的座位并回到等车区，保留地点、时间和备注。若不再参加出行，可使用“不参加了”删除本场活动的登记。登记关闭后由管理员调整。
- 公共交通和其他自行前往也有快捷退出按钮，点击“退出公共交通”或“退出自由出行”后回到等车区，保留已有地点、时间和备注。
- “我的出行安排”、自己的等车详情、所在车辆详情，以及已选择的公共交通或自由出行详情都提供“不参加了”。点击后先确认，确认后删除本场活动的人员登记，不转入等车区，之后仍可重新报名。司机确认不参加时，车辆一并取消，乘客回到等车区；登记关闭后由管理员调整。
- 司机可在自己车辆的乘客列表中单独点击“移回等车区”。该乘客的座位立即释放，地点、时间和备注保留，其他乘客及车辆不变。操作需登记开放，并校验乘客当前车辆和登记版本。
- 修改司机出行方式需要确认取消原车辆；直接取消车辆也会展示确认页。原乘客返回公开的等车区，已有需求保留，缺少的信息可暂时为空。车辆取消不再创建后台提醒。
- 主动请求协助同样只留下后台提醒，前台不显示待安排状态，也不占用姓名。重新登记后，后台可看到最新登记方式，提醒由管理员手动确认完成。
- 容量不能小于已有乘客人数。管理员分配乘客同样受容量限制。
- 关闭登记后，成员保留查看功能；管理员可继续调整。
- 出发广场约每 3 秒在后台检查一次变化，无变化时只返回版本信息；有变化时局部更新车辆、人员和详情，不重新加载整页。普通成员和管理员的广场都支持同步，后台列表和独立编辑页不自动同步。
- 同步保留当前选中区域和滚动位置；选中的对象已离开对应区域时，回到当前安排或可用区域。输入、拖动、滚动或尚未提交选车操作时暂缓应用更新，页面会提示有新安排。可以完成操作，或点击“放弃当前选择并同步”。切到后台标签页时暂停检查，网络恢复后自动重试。
- 所有提交仍重新检查座位、权限和登记版本。重复提交或旧记录覆盖新记录时提示重新加载；编辑页中的内容不会被自动同步覆盖。切换姓名或管理员身份后，旧标签页暂停同步并提示重新加载。

## 备份与更新

双击 `backup.cmd`，或运行：

```powershell
.\.venv\Scripts\python.exe manage.py backup
```

备份工具通过 SQLite Backup API 获取一致的数据副本，可在网站运行时使用。生成的 ZIP 位于 `instance/backups/`，包含数据库和管理员配置；请妥善保存配置及备份。

恢复时先停止网站，保留现有 `instance` 目录的副本，再将备份中的 `gotogether.sqlite3` 和 `config.json` 放回该目录，随后启动。更新程序时保留整个 `instance` 目录，替换应用代码后重新运行 `setup.cmd` 更新依赖。当前数据库版本为 13，旧版数据库会在启动时按需通过 `migrations/` 目录中的 `migration_2.sql` 至 `migration_13.sql` 自动升级，活动、车辆、登记及原有后台提醒保留；尚无车牌字段的旧车辆默认为空车牌，尚无外观字段的旧车辆默认为小米 SU7，已有外观保持不变，尚无颜色字段的 SU7 默认使用卡布里蓝。版本 10 增加 CT5 外观，版本 11 增加比亚迪汉，版本 12 增加马自达 929，版本 13 增加三体水滴，均保留已有车辆编号、配色和乘客关联。升级在同一个事务中完成，从版本 1–12 升级要求 Python 所用的 SQLite 版本不低于 3.35。升级前建议运行 `backup.cmd` 保存一份备份，升级后请使用新版程序。

## 项目结构

- `app.py`：页面路由、会话、CSRF、管理员权限。
- `store.py` / `schema.sql`：数据库和共用业务规则。座位检查和写入位于同一个 `BEGIN IMMEDIATE` 事务。
- `migrations/`：旧版数据库的增量升级脚本，按版本顺序执行。
- `templates/`：活动、登记、后台页面。
- `static/`：场景模型、响应式布局与操作动画。
- `static/vehicles/`：十四种车辆按车辆 ID 分目录，默认外观为 `<车辆>/default.webp`，其他外观为 `<车辆>/<外观>.webp`；主图统一为 640 × 440 的透明 WebP。SU7 色卡保留 140 × 140 的 PNG，位于 `su7/swatches/<颜色>.png`。
- `design/`：按 `<车辆ID>/<主题-日期>/` 归档原始素材、参考图、提示词和来源记录；旧版 SU7 成品位于 `design/su7/study-20261014/su7-legacy.webp`。跨车型对比页、拼图和汇总索引集中在 `design/comparisons/`。
- [车辆与皮肤资源规范](design/README.md)：图片规格、全部在用主图与色卡的来源对应表，以及新增车辆和皮肤的接入步骤。
- `run.py`：Waitress 启动入口。
- `manage.py`：管理员配置与备份。
- `tests/test_app.py`：使用临时数据库的业务、权限和并发检查。

## 验证

实现时按工作区约束做静态审查。需明确授权执行后，再运行以下检查与实际浏览器验收：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

浏览器重点核对姓名入口、活动链接直达、创建车辆及车牌、换车、等车登记、司机点击和拖动接人、各方式快捷退出、取消车辆后的等车记录、关闭登记，以及窄屏场景选择与操作动画。用两个浏览器核对广场同步、当前选择和滚动位置保留、输入或拖动时延后更新、断网恢复和身份切换。

本项目直接运行 Python 服务，首版没有 EXE 打包步骤。
